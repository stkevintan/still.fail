隐私政策

生效日期：2026 年 11 月 25 日

本政策说明 still.fail 托管服务会收集哪些个人信息、怎么用、交给谁、存多久，以及你有哪些权利。请仔细阅读，特别是加粗的部分。

1. 谁在处理你的信息

still.fail 由一位位于中国大陆的个人开发者运营（下称“我们”）。关于个人信息的任何问题和请求，请发邮件到 hi@still.fail。

2. 本政策适用于哪些服务

本政策适用于我们运营的 still.fail 托管服务，包括 still.fail 官网、网页版（app.still.fail）、公开分享页（share.still.fail）、预览页（preview.still.fail），以及连接这些服务时的桌面应用、Android 应用和 iOS 应用（合称“本服务”）。测试渠道 youdid.wtf 也适用本政策。

以下情况不适用本政策：

  • 你自己机器上的 station：station 运行在你自己（或你所在 workspace 成员）的电脑或服务器上，聊天记录、文件和 agent 的工作都保存在那里，由你和你的 workspace 控制，我们无法访问。为了丢一台机器不丢聊天，每台 station 还会把它的聊天（消息、聊天里的附件和会话记录；不含 agent 的执行记录、工作目录和已登录的账号）备份到同一 workspace 的另外两台 station 上，从不备份到其他 workspace 的 station 上。workspace 里新加的 station 可以从这些备份恢复丢失的那台的聊天。备份在你的 station 之间端到端加密传送，不经过我们的服务器；
  • 别人用 still.fail 开源代码自己部署的服务；
  • 你在 station 上使用的第三方服务，例如 Claude、ChatGPT/Codex、Hermes Agent、Pi 及你为它们配置的模型服务、Google 的 Antigravity CLI、Google Vertex AI 与 Google Colab、Slack、GitHub。它们适用各自的隐私政策。

3. 先说最重要的：聊天内容不存放在我们这里

still.fail 的 agent 运行在你自己的 station 上。你的设备和 station 之间是端到端加密的直接连接；直连不通时，会经过中继服务器转发，中继只转发加密数据，看不到内容。我们的服务器不保存你的聊天内容、附件和文件。

全局 mesh 中继的登记由服务器运营方管理。服务器保存中继名称、公钥、引导网络地址、注册代次、地址版本、添加者和时间；移除后保留登记记录以拒绝旧代次的地址更新。登记信息用于引导连接，不包含 workspace 成员目录、实时路径或链路质量。公共中转节点只接收相邻节点和当前通路所需的身份信息，空闲通路的身份缓存会清理。

workspace 的 mesh 目录由其 station 保存和交换：包括节点公钥、签名的网络地址、中转能力和版本号，用于发现可用通路。workspace 中继注册还保存中继名称、签发 station、添加者和撤销版本；撤销记录保留以防旧身份重新生效。一次性注册 token 有效期为 24 小时，station 只保存其摘要；兑换成功时删除摘要，未兑换的过期摘要在该 workspace 下次签发时清理。这些目录和注册记录保存在 station 的数据库中，随 station 数据删除；不会发送聊天内容，链路质量测量留在节点本地。

有两个例外，内容会经过或保存在我们这里：

  • 推送通知：为了在你的设备上弹出通知，station 会把聊天标题、发言人名字和消息的前 140 个字经我们的服务器转发给 Google 的 Firebase 云消息（Android）、Apple 的推送通知服务（iOS）或你浏览器的推送服务（网页）。我们只转发，不保存这些文字。在某台设备上关掉「通知里显示内容」后，发往这台设备的通知只说发生了什么（如「有新消息」），消息的文字不再转发；
  • 问题反馈：你或你的 station 上的 agent 主动提交的问题反馈（标题、描述、上下文、已知时受影响的桌面系统和日志）会保存在我们的服务器上，用于排查问题。still.fail 团队对一条反馈的回复，以及你的 agent 对它的回复（回复内容、时间、回复人，以及团队的回复是否已送到提反馈的对话）也随这条反馈保存；团队的回复经你的 station 交给提反馈的对话。

打开远程终端时，station 随终端记录创建者的邮箱，并传给该 workspace 的设备，用于将长时间运行的终端提醒发给创建者。

公开分享的聊天也保存在发布者的 station 上，访问者的浏览器通过加密连接直接从 station 读取。分享链接中 # 后面的密钥不会发送到我们的服务器。

预览 GitHub Actions 运行链接时，你的 station 会向 GitHub 查询这次运行及其任务。如果 station 已登录 GitHub，会使用该登录身份。你的设备会保存最近的链接预览，包括运行和任务的状态、步骤名以及 GitHub 日志链接。

使用共享调试时，station 在授权有效期间保存该对话最近一次实际调试的时间，并通过加密连接发给你的设备，用于显示和排序；授权结束后从该授权记录中移除这个时间。记录这个时间时不会保存调试命令的内容。

station 可以设为「只执行任务」：不运行 agent、不保存对话，只替 workspace 的其他 station 执行任务，归添加它或把它设为这种模式的成员所有。这样的 station 在自己的机器上保存所有者为它签发的授权（对话的标题、发起人的邮箱、授权方式和期限）和它被要求执行的命令记录（时间、来自哪台 station 的哪个对话、命令的前 2000 个字符）。授权结束后从这台机器上移除，被收回的授权只留编号到原定期限为止；命令记录超过 4 MB 时只保留最近的两个文件。对话所在的 station 保存这次申请及其结果。完整的 station 改为只执行任务后，它已有的对话仍留在这台机器上，改回完整之前不再提供。这些内容通过加密连接在你的设备和各台 station 之间传递，不经过我们的服务器。

成员可以把设备（手机、开发板、摄像头、路由器、串口等）接到 station 上，供 agent 使用。设备接在哪台 station 上，就由那台 station 保存它的名字、类型、连接地址（地址和端口、串口路径或 adb 序列号）、添加它的成员和添加时间；接在只执行任务的 station 上的设备，还保存所有者为它签发的授权和免批准设置，连接记录写进这台 station 的命令记录。对话连接设备时，数据经加密连接在对话所在的 station 和设备所在的 station 之间直接传递，不经过我们的服务器，也不被保存。移除设备后，这些信息从 station 上删除。

你的预设和收藏的模型保存在你的设备连接到的 workspace 的每台 station 上，所以在你的所有设备上都一样：每个预设（名称、文件夹、给 agent 的说明、开对话用的模型和 station、谁在何时创建、改过几次），删除的预设只留它的编号、所属的人、改过几次和删除时间（每个 workspace 保留最近的 500 个），以免被别处的旧副本带回来；收藏的模型保存每个模型的标识、是否收藏和收藏时间。它们由你的设备经加密连接带到各台 station，不经过我们的服务器。workspace 的成员和 agent 都能看到 station 上保存的预设。

看板「待派发」里还没开始的任务同样保存在你的设备连接到的 workspace 的每台 station 上，所以在你的所有设备上都一样：每条任务的文字、选定的 station 及其名称、所附文件的名称和大小、写下和修改的时间、改过几次（每人每个 workspace 最多 200 条）；开始或删除的任务只留它的编号、所属的人、改过几次和时间（每人每个 workspace 保留最近的 200 条），以免被别处的旧副本带回来。任务所附的图片和文件保存在这条任务选定的 station 上，任务开始或删除后再保留一天，以便开始它的设备把文件发进对话，然后删除。这些内容由你的设备经加密连接带到各台 station，不经过我们的服务器。app 只把待派发显示给你自己；和 station 上的其他数据一样，workspace 的 agent 能读到它们。

在密钥库里用「添加 › Slack 账号」时，你在 Slack 的页面上授权，Slack 把浏览器送回网页版的一个页面（/vault/oauth），这个页面只在你的浏览器里把授权码交回发起授权的那台设备。打开这个页面的请求会经过我们的静态网页服务器，地址里带着授权码，但服务器不保存它；没有只存在发起设备上的校验值，这个授权码也换不出令牌。那台设备直接向 Slack 换取你的个人令牌，并查询它属于哪个 Slack 账号，然后把令牌、你的 Slack 用户名和 Slack 工作区名称存进你的密钥库，和你手动添加的令牌一样保存。发起授权时，设备会暂存一次性的校验值，最多保存一小时。在 Slack 里取消这个应用的授权，或在密钥库里删除这一项，令牌就不能再用了。

在 Monoid console 里给一台机器点「连接」时，console 把浏览器带到网页版的一个页面（/connect/station）。你在这里选一个由你管理的 workspace 后，这个页面像在应用里添加 station 一样生成一次性的加入命令（含加入用的令牌，一小时内有效），并用表单直接交给发起请求的 console，由它把命令下发到那台机器；命令不出现在网址里。我们只把命令交给认可的 console（console.monoid.computer），不另外保存；之后由 Monoid 按它的隐私政策保存和使用这条命令。

处理 Comma Router 的聊天写入时，station 在本机保存去重键及对应的聊天和消息编号，避免重试时重复写入；投递完成前还暂存当时的接收会话。记录超过 31 天后在后续写入时分批清除，空闲时保留到后续写入。去重记录不另存消息正文。

连接 Comma 时，station 在本机按 Comma 连接所属的工作区（主工作区或加入的工作区）保存发送给 Comma 的使用统计和聊天索引，包括聊天标题，以及 Comma Router 是否在各个聊天中写过消息；对在等人的聊天（等人回复、已完成但发起人未读、出错），还包括所等之人的邮箱、agent 对需要什么、做完了什么或出了什么错的一句话说明，以及该聊天在 still.fail 中的链接。刷新索引会更新最近 31 天的统计；较早的索引行和以前版本留下的索引文件可能保留到删除 station 数据时，更换工作区不会自动删除它们。

为了在 Profile 的概览里画出额度的变化和消耗速度，station 在本机为每个账号按小时保存它读到的订阅额度（各额度窗口的名称、已用百分比、重置时间和窗口长度）。每个账号最多保留最近 192 小时（8 天），写入新的一小时时删除更早的记录；删除账号时一并删除。每个小时、每个模型上的调用用量（调用次数和 token 数）不另外保存，而是从 station 已有的按 15 分钟汇总的用量统计中读出最近 192 小时。为了在概览里画出各类模型的输出速度，station 还从 agent 的对话记录里的时间戳算出每次模型调用用了多长时间，和这次调用写出的 token 数一起记在同一份用量记录和按 15 分钟的汇总里，随它们保留和删除；启动时会把最近 8 天里还没算过耗时的调用补算一次。这些内容只通过加密连接发给你的工作区成员的设备，不经过我们的服务器，也不含对话内容。

扫码创建飞书机器人时，station 会在自己的机器上暂存扫码链接、设备代码、创建者、所选连接设置和飞书返回的机器人凭据，以便重启后继续保存。连接保存成功后，暂存的凭据和链接会被移除；已完成或失败的注册记录在扫码有效期结束 24 小时后删除。机器人已建好但连接尚未保存时，凭据会保留以便重试。连接本身的凭据保存在 station 配置中。

4. 我们收集哪些信息

  • 账号信息：用 Google 登录时，你的 Google 账号标识、邮箱、名字和头像链接；用 Apple 登录时，你的 Apple 账号标识、邮箱（含你选择隐藏邮箱时 Apple 提供的中继邮箱）、首次授权时提供的名字，以及一份加密保存的 Apple 刷新令牌（仅用于在你注销账号时向 Apple 撤销授权）；用邮箱验证码登录时，你的邮箱。另有账号的创建时间、最近活跃时间，以及套餐、资格和封禁状态；
  • 登录会话和设备：设备或客户端的名称（如电脑名、手机在系统设置中的名称）、会话的创建和到期时间、设备首次和最近在线的时间；
  • workspace 信息：workspace 名称、成员和角色、邀请（包括被邀请人的邮箱）、邀请码，以及加入的 station 的名称、图标、版本、在线时间和模式（完整或只执行任务），只执行任务的 station 另有它的所有者；
  • 推送令牌：你的设备或浏览器为接收通知而登记的令牌或推送地址，以及这台设备的通知设置（语言、接收哪几类通知、是否显示内容）；
  • 问题反馈：见第 3 节；
  • 管理操作记录：still.fail 团队在管理后台对账号、workspace、邀请码、问题反馈和中继做的修改，记下操作人、时间、做了什么，以及被修改的对象（如账号的邮箱、workspace 的名称、反馈编号），用于团队内部核对谁改了什么；
  • 网络和日志信息：访问本服务时的 IP 地址、请求路径、时间和浏览器信息（User-Agent），记在 Cloudflare 的请求日志中；中继服务器能看到连接的 IP 地址、节点公钥和流量大小。为防止滥用，我们用加盐哈希后的 IP 地址和邮箱来限制登录频率；
  • 使用统计和错误信息：网页版和 Android 应用会向 PostHog 发送操作事件、次数、耗时、程序错误和调用栈。iOS 应用发送的程序错误是 iOS 在应用下次启动时交给它的闪退和卡顿报告（Apple 的 MetricKit：调用栈的地址、异常类型、应用版本、设备型号和系统版本），报告先保存在这台设备上，登录后发送；Mac 应用也发送它遇到并处理掉的程序错误。各端应用（Android、iOS、macOS、Windows、Linux 和网页版）还会每隔一段时间向 PostHog 发送一次功能的使用次数：用了哪些功能（只有程序里写定的操作名，比如发消息、归档对话、修改设置）、打开了哪类页面（只说页面类别，比如一个对话、设置里的哪一页，不说是哪个对话、哪台 station 或哪个文件），各多少次，以及应用的平台和版本；不含操作的内容和参数、输入的文字和消息内容。Android、iOS 和 Mac 应用还会发送界面卡顿的记录：卡住的是哪类工作（输入、绘制、系统回调）、各用了多少毫秒、绘制、新建和排版了多少元素、测量了多少段文字，以及应用在前台时卡顿的次数和按耗时分档的帧数，还有卡顿时显示的是哪类页面（一个对话、对话列表、设置里的哪一页），这些次数也按页面类别分开，以及卡顿时界面按小屏、中屏还是大屏排布、窗口的宽和高；只说页面的类别，不说是哪个对话、哪台 station 或哪个文件，不含输入的文字和消息内容。这两个应用还会发送应用内部收到的各类数据有多大（Android 应用切换页面时这一页收到的，以及发来后没有用到的）：只有数据类别和字段的名字、字节数和条数，不含数据本身。这些数据只以你的账号 ID 标识，不附带邮箱和名字。你可以在应用的设置中关闭“发送使用统计和错误报告”，关闭后这台设备不再向 PostHog 发送任何数据。客户端、station 和服务器还会向 Google Cloud 发送请求链路追踪，包括账号 ID、会话 ID、请求路径和耗时，以及连接走的线路、来回时间和 app 回到屏幕上之前离开了多久；云端收到这些追踪和下面的 station 运行日志时，还会附上它们发出时所在的网络（运营商、国家或地区、省份和城市，不含 IP 地址）。这些统计和追踪不包含聊天文字、文件名、提示词、agent 输出和对话标题。链路追踪用于排查故障和性能问题。关闭“发送使用统计和错误报告”后，这台设备也不再发送链路追踪，它发出的请求会注明不要记录；此后服务器只为排查故障记下其中失败、被限流或很慢的请求。station 默认还会向 Google Cloud 发送运行日志（station 做了什么、什么时候做的：它和 still.fail、和其他 station 的连接，错误，版本；附带它运行的操作系统、CPU 架构、运行引擎和角色（完整 station 或只执行任务），以及进程内存、打开的句柄数、数据目录所在磁盘的剩余空间和数据库日志（WAL）大小等诊断计数，以及进程异常退出、无响应被重启或网络前端重启等启动器的恢复记录：退出原因、运行了多久，以及重启前的内存和连接状态摘要），发送前去掉家目录路径、邮箱、像密钥或令牌的字符串、引号里的文字和可能是人写的字段，不包含聊天文字和文件内容；workspace 的管理员可以在应用里 station 设置的「诊断」中关闭「发送运行日志给 still.fail」，也可以在 station 的 config.json 里关闭（"telemetry": { "logs": false }）。发往 PostHog 的 station 错误报告只有在 station 的使用者开启后才会发送，默认关闭。

still.fail 官网（still.fail）本身不使用统计工具。

5. 我们怎么使用这些信息

  • 让你登录，识别你的账号、设备和 workspace，让你的设备找到并连上你的 station；
  • 发送登录验证码和通知，以及告诉被加入 workspace 的人是谁把他们加进了哪个 workspace 的邮件；
  • 执行套餐额度，防止滥用和攻击，保障账号安全；
  • 排查故障，了解功能的使用情况，改进本服务；
  • 回复你的问题和请求，履行法律义务。

我们不出售你的个人信息，不用它投放广告，也不用你的数据训练 AI 模型。

6. Cookie 和本地存储

  • 登录过程中使用一个 10 分钟有效的 Cookie，用于安全地完成登录；
  • 网页版把登录凭据和应用数据存在浏览器的 IndexedDB 中，把界面偏好（主题、侧栏宽度等）存在 localStorage 中；
  • 网页版的 PostHog 统计会在浏览器中保存自己的标识，以及你是否关闭了统计。

我们不使用第三方广告 Cookie。

7. 我们把信息交给谁

8. 个人信息出境

由于上表中的 Cloudflare、Google、PostHog 位于中国大陆以外，你的账号信息、设备和 workspace 信息、推送通知文字、使用统计、错误信息和日志会传输到中国大陆以外（主要是美国）存储和处理，用于第 5 节所列的目的。你可以按第 10 节的方式，向我们或这些接收方行使你的权利。境外接收方的联系方式见各自的官网。你登录并使用本服务，即表示你同意上述出境传输；如不同意，请不要使用本服务。

9. 我们保存多久

  • 登录验证码：10 分钟，用完即删；
  • 登录会话：最长 30 天，连续 7 天不用即失效；
  • 邀请：7 天；
  • 加入 workspace 的通知邮件发给了谁（workspace、邮箱和时间）：用于 24 小时限频，过期记录在下一次添加成员时清理，workspace 删除时也会清理。发送失败时，另存 workspace 和邮箱作为待重试记录，供再次添加时重发，这份记录不含邮件正文或失败原因；重发成功、成员或待加入关系被移除、workspace 被删除或收件人的账号被删除时清除，除此之外仅在该关系仍存在时保留；
  • 推送令牌：退出登录或设备不再接收时删除；
  • 账号、workspace 和 station 信息（含 Apple 登录关联记录与加密保存的 Apple 刷新令牌）：在你使用本服务期间保存，注销账号或删除 workspace 时立即删除（并向 Apple 撤销登录授权）；
  • 问题反馈及其回复：问题处理完后视需要保存，注销账号时一并删除，你也可以随时要求删除；
  • 管理操作记录：只保留最近 1000 条，更早的自动删除；注销账号或删除 workspace 不会改写此前已记下的条目，你可以随时要求删除其中与你有关的条目；
  • 请求日志、使用统计、链路追踪和 station 运行日志：分别按 Cloudflare、PostHog、Google Cloud 的保留期限保存，到期自动删除。

法律法规要求更长保存期限的，从其规定。
