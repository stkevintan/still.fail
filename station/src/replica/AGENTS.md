# The copies of a station's conversations (for agents)

Losing one machine does not lose a workspace's conversations (the user, 2026-11-09). A station's chats (threads, entries, letters, sessions, turns, viewers' marks, attached files) and runtime session transcripts (`transcripts*/` and Antigravity CLI `homes/<profile>/agy/.gemini/antigravity-cli/{conversations,brain,annotations}`, excluding the three derived cache subtrees `brain/<id>/.system_generated/steps`, `brain/<id>/.system_generated/logs/chunks`, and `brain/<id>/scratch` on export while keeping the restore whitelist intact for older backups; chunked at 4 MiB with zstd CAS, unreadable-path protection, `tr_del` batch throttling at 2,000/pass, a sweep cut by the pass budget going on at the path it stopped at rather than from the first (derived-cache `tr_del`s still drained while it is cut; transcripts told of during a sweep bring another sweep after it; chunk GC after each whole sweep), and `carriedTo` project remapping on restore; optional per S3 target via `includeTranscripts`) are copied per workspace to keeper stations and S3/R2 targets; a new station takes them back for a lost one. Usage, accounts, browser sign-ins and working directories (`sessions/*/workspace`) stay the machine's and are never backed up.

## The copies

- Export and restore run off the main thread in MoonBit (`station/mb/src/replica`; `runner.ts` `exportThread`, `restore.ts` `takeBackSoon`). No TypeScript fallback: it matches the old TypeScript line for line, kept only in tests (`station/test/reference/replica-export.ts`, `replica-restore.ts` `takeBack`, `replica-format.ts`; `station/test/mb-replica.test.ts` holds them to each other; `replica-work.ts` `InlineRunner`). `src/replica/` keeps only the station's side (`export.ts`, `format.ts`). The export reads stillfail.db only: immutable batches, a generation per workspace, `head.json` last. Changes come from what tables give (append-only rowids, an index, store change notes, digests in `export.db`), never a trigger or statement on the write path (`replica-export-bounded.test.ts`).
- Keepers hold batches and files opaquely (`places.ts`): by default the two other workspace stations of highest rendezvous hash (`peers.ts keepers`, skipping peers that declare `acceptCopies: false` in `replica.hello`). Backup targets are configured in station-local `config.json` `backup` (`backup-config.ts`, `GET`/`PUT /copies/settings`, `POST /copies/s3/test`, `GET /copies/history` backed by `<data>/replica/history.json`): `stations` (`"auto"` or a manual station-id list, `[]` for none), `acceptOthers` (default `true`; `false` refuses `replica.put` and hands over kept copies), and optional S3/R2 targets (`s3.ts` `S3Place`) encrypted end-to-end with `SFB1` streaming ChaCha20-Poly1305 (`crypto.ts`, mirrored in `station/mb/src/replica_coord/`). Secrets (`secretAccessKey`, `encryptionKey`) stay in `config.json` (`0600`) and are never returned in `overview` or `GET`. No follower database or merging: only a restorer reads a batch (`restore.ts`), into a station with no chats of its own, before its store opens (from a peer or an S3 target via `{ s3 }`).
- A pass and `export.db` commit together, after the head naming its batches. A batch is at most BATCH_BYTES; folds and restores use SQLite on disk and stream files, so heap stays flat (`replica-heap-bounded.test.ts`: 24 MB heap).
- A place's holdings are remembered (`places.ts Known`); only new batch and head are sent; while transcripts are still to send, a `partial` head naming only those held goes first (always inline `transcriptFiles`, never pointing at an unverified manifest), so the chats never wait behind a first copy of transcripts; its listing is asked only at start, hello, failure, handover. Remote file deletion in `level()` pages `place.drop()` at `DROP_FILES_PAGE` (2,000 files/call); `S3Place` reclaims objects via `POST /?delete` (`DeleteObjects`, 1,000 keys/request with `Content-MD5`) and reconciles post-crash orphan `files/<tag>.enc` in `pruneOrphans()` only when every listed `head/<gen>.enc` and any referenced `transcriptManifest` root/leaves verified cleanly (if a permanently corrupted/unverifiable `head/<gen>.enc` or manifest exists in the bucket, `hasUnverifiedHead` is set and remote file `drop` and orphan cleanup conservatively pause until resolved). While a keeper is unreached, the next in rendezvous order holds the copy (`replica-stations.test.ts`).
- Two-level 256-bucket canonical pure JSON `transcriptManifest` (`manifest.ts`, `station/mb/src/replica/manifest.mbt`): root `{"v":1,"buckets":{"00":"<leafHash>",...}}` (sorted ascending, empty buckets omitted) and bucket leaves `{"v":1,"files":{"<chunkHash>":<compSize>,...}}` (sorted ascending, prefix matching bucket, non-negative safe integers, no whitespace, no zstd). Every read strictly verifies SHA-256, `v === 1`, no extra top-level keys, no duplicate JSON keys, bucket prefix match, and hard anti-bomb caps (64 MiB total manifest bytes, 500,000 total entries, 256 buckets). Dual-field coexistence (`transcriptFiles` + `transcriptManifest`) is tolerated: protection/retention sets take the union, download/materialization prefers `transcriptManifest`. In D72a, disk `own/<ws>/<gen>/head.json` and outgoing wire `put("head")` keep inline `transcriptFiles` for zero-rollback risk, while local `WorkPassed.heads` IPC carries compact `transcriptManifest` backed by `<replica>/manifests/<hash>` (atomic tmp + fsync + rename, 10-minute mtime GC grace; missing local manifest rebuild from `own` `head.json` is accepted only when its recomputed canonical root hash strictly matches). `Known` caches confirmed `(gen, strategy, manifestRootHash)` to avoid re-expanding unchanged manifests without skipping chat attachment `oldFiles` or pending `drop()` pages. Remote manifest objects reuse the content-addressed `files/<hash>` slot (`FolderPlace`, `S3Place`, `PeerPlace`); `FolderPlace.put("head")` validates full manifest closure (root + all leaves + all chunks) under `#withLock`, and `FolderPlace.drop()` fails closed on any corrupted `head.json` or manifest. `handOver` / `holdsAllLogical` strictly distinguish `partial` vs full heads and compare heads by logical equivalence across inline `transcriptFiles` and `transcriptManifest`. `restore` verifies `transcriptManifest` root/leaves strictly (failing on corruption) while preserving chat-first tolerance for missing individual transcript chunks (`missing`).
- A restore's steps (rows, files, `formerly`) each run again safely; its outcome stays (`restore.ts outcomeFile`) past restart. What it brought is let go only once files are placed (or rows never went in); rows in and files not, the next start places them. It folds batches on disk and puts each final row in once, so triggers see it once; batches or the folded generation give the same database (`replica-export.test.ts`). It is refused, early and before restart, on a station with chats of its own (a retired station's aside).
- Batches hold only their workspace's chats; a station leaving a workspace deletes its copies. A copy no longer kept goes only once new keepers hold as much; handover defers while `replica.put`/`replica.drop` writes are active or within `HANDOVER_QUIET_MS` (15 s, skipped when `acceptOthers` is `false`), re-checks the write sequence before removal, atomically renames to `.dropping-*` under a short gate before deleting outside it, and primary-keeper recovery cancels non-target overflow retries.
- A station rolled back finds a place ahead of it (`places.ts behind`): it starts a generation; the place keeps both; nothing merged or dropped.

## Carrying a chat's files (`carry.ts`)

- MoonBit (`--builder replica-carry`, `station/mb/src/replica/carry.mbt`), a process each, killed on cancel, no worker fallback (`station/test/carry-reference.ts`, `station/test/mb-replica-carry.test.ts`). It takes a session's room whole (archived: its packed workspace; `footprint.ts roomOfSoon`; a directory not the station's is counted and left) and its transcripts, by bytes, to the same places under the other's data directory, only under `sessions/` and `transcripts*/`.
- Antigravity CLI's conversation in its profile home goes too (`cliKept`: `session/load` reads it there); the profile there brings it in whole from the home that wrote it last (agents/agy.ts `agyBringIn`; without: "trajectory not found", 2026-11-16). A hand-over's prune removes what the second pass no longer names (handover.ts `#prune`: a `-wal` left beside a newer database was replayed into it, malformed, 2026-11-16).
- A checkout's files go as git lists them; `rebuildable` stays: by name anywhere, by contents only outside a checkout within 3 levels of the room top (carry.mbt `rebuilt_by_name`, `rebuilt_of_any_name`, held to `station/test/footprint-reference.ts` by `station/test/mb-replica-carry.test.ts`). Its `.git` goes as files, walked after the room (a linked worktree walked later fetched into it and was refused as changed, 2026-11-16). Linked worktrees are remade by git (remote fetched and pruned, a bundle of unpushed commits, `git worktree add`, `repair`); failing that the bundle sits beside it; none without git there.
- A station has a million files: none is an object on the main thread or in one message (lists per session on disk, an index, bounded hash batches; `replica-retire.test.ts`). Each file is hash-checked as written and placed by link, no byte copied (`carry.mbt` `put_file`); one already linked elsewhere is copied, so two paths never share a file (2026-11-14: Node's clone copied bytes on APFS and filled a disk).

## Retiring a station (off)

- `retire.ts` handed every chat of a workspace to a station a person picked (the user, 2026-11-13: 「搬家主要考虑的场景是要废弃掉一个 station」, 「要允许用户选择目标迁移 station」; 「避免脚本乱改改错」), on two owner/admin cards (`retire-asks.ts`). Since its first real use it is off (左子健, 2026-11-14: 「我怀疑这个功能根本不能给用户用」): POST /retire and station_retire's start and hand_over are refused (module.ts `RETIRE_STARTS`) until fixes pass a drill. `station_move` (`station/src/move/`) replaces it. Its restore `merge`, `formerly`, `moved_notes`, `agent-carry.ts` serve hand-overs too.

## One chat handed over (`handover.ts`)

- One chat moves while both stations are up (左子健, 2026-11-14, superseding 2026-11-09; a whole station is every chat, then connects and logins; the reverse hand-over is the way back): the `chats` module of `station/src/move/`. State is a file per side (`handover/out/`, `handover/in/`); only `handed_over` is in the schema (store `handOff`).
- The chat is held alone (sessions/hub.ts `holdChat`), its files gathered (carry.ts `gatherSoon` `keys`) and sent (`sending.ts`; flushed once a placing, `flushOnce`; macOS may lose some, so one still coming as that machine restarts is dropped, `boot`). Rows go in pages through the other's store, hidden until shown (store/handover.ts, `comingWs`); each thread's log continues past what that station has (n kept where it was this chat's, else by ts), so a chat handed back appends.
- Each station keeps its numbers: an arriving entry equal at its number is skipped, one found by ts is that one, others are numbered on, nothing renumbered (it would rewrite a hidden copy's rows and all hanging on them, 「避免脚本乱改改错」). A copy with entries of its own (a retirement's leftover, 2026-11-14) keeps every entry once, orders differing only there.
- A chat whose key is live there is never merged into: the plan refuses it (`move.chats.live`), as does `handover.begin` before any write. Undelivered input goes along, marked handed here once shown there (store `deliveredThere`), never given twice. Spend (`usage`, `usage_files`, `session_usage`) goes with its rows (`handover.begin` `usage`, `AFTER_SHOWN`), once per call id, threads and accounts mapped, summary recomputed; earlier chats send theirs in pages when heard (`handover.usage`, `usageSyncedFile`, two hops).
- It is gone here only once the other counted it; before, a failure undoes it there and it goes on here (`handover.drop`: answered once rows are out; that station then removes what it placed, its directories, a linked worktree with registration, branch, ref (not the repository), and restores what it set aside). A newer hand-over drops an older one still coming first (`#serialIn`); a drop is owed until answered, even to a gone station.
- No request waits on work growing with the chat: placing (with worktrees) and pruning are told steps (move/told.ts, `station/src/move/AGENTS.md`); `handover.lacking` hashes at most `HASH_MOST` bytes a request (rest `unchecked`). The receiver drops it itself when its disk fails (full, quota, read-only: refused in numbers, never a stream reset, mesh/peer.ts `Incoming.held`), or when one still coming no longer goes on at the sender (`handover.still`); after, nothing is undone.
- One process acts on hand-overs at a time: a new one waits for the old to go (`previous`), as does a move turn (move/station.ts `refusal`). The end, gone or failed, is decided once (`decided`, a file linked into place).
- A chat marked `handed_over` whose last hand-over failed unshown, or sits at `gone` unshown where that station denies holding it (`handover.held`; an unanswered show is left to retries), is checked at start and when heard from: shown there, the record completes; else it shows here again, failed (`#mend`; real run 2026-11-15: a chat on neither station).
- Platform threads are re-pointed to where their connect runs (connects/workspace.ts `route`, `connect.route`); what still comes here goes there (`movedTo`). Devices are redirected (409 `moved`, `GET /moved`, `chat-moved`) only once that station showed it (store `goneTo`, `shownThere`; told at `gone`, a device kept 「对话不存在」, drill 2026-11-14); until then it reads here, held, and what arrives follows (`caught`). Nothing is posted in it; its agent is told once (`moved_notes`).
